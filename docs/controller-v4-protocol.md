# v4 控制器真实验证与任务校准方案

本方案在新调用前提交，旧 38 次请求的方案和结果不覆盖、不合并成功率。任务、初始源码、评分器、模型和 Docker 隔离沿用已公开版本。

## 先验证流程，再测任务

先在 dotenv-comment 上执行 1 次无技能工程验证。验收是三个阶段完成并获得有效的最终隐藏评分；补丁可以通过或失败。这样确认的是评分链路，而不是挑选成功样本。

工程验证达到验收且费用字段完整后，再执行独立的 4 次校准：dotenv-comment 与 dotenv-backslash 各 2 次，seed=2718 固定排期，每次从初始源码开始。工程样本不计入校准结果。若流程验收失败或费用未知，后续任务不调用，明确导出未执行排期。

## 固定运行条件

- DeepSeek deepseek-flash、非思考模式、请求 temperature=0；无技能。
- 每次最多 10 次模型请求、每阶段最多 4 次、单次输出最多 2,048 tokens；输入 JSON 最多 64 KiB。
- 阶段额度结束时由运行器切换，交接真实工具日志，明确标记没有模型分析总结；仍可由模型提前总结结束。
- 调查与验证阶段只读，只有实现阶段可修改声明文件；模型最多 2 次公开测试，最终隐藏评分不反馈模型。
- 最多 5 次运行、50 次请求，按仓库固定高峰价的费用估算上限 USD 1.50；每次开始前为整次保守预留。无自动付费重试，费用未知停止。
- 执行前固定输入、工具代码指纹、排期和镜像 ID。新请求前检查未变化。全部失败与停止均保留，不替换或补跑。
- dotenv-bom 保留题不调用模型或评分；不同协议、工程样本与校准样本分开。

## 结果如何解释

先报告流程是否到达最终评分，再分开报告代码功能失败、格式/截断/额度失败、接口与基础设施错误。每题公开两次状态、隐藏测试数、工具次数和费用。两道同源库题不能证明泛化能力。

如果校准出现成功和有效隐藏功能失败，可以继续设计技能对照；若全通过或全失败，先扩大任务池或预先登记新的匹配预算校准，不直接制造冲突或启动自动策略学习。未知故障不能当作功能失败。后续方案必须在下一批调用前固定。
