# 多文件 Agent 冒烟测试方案

本方案先提交，再执行一次真实模型运行。任务是人工编写的购物车金额修复夹具，不是来自真实开源 issue 的样本。

## 目的

验证模型能否通过受限工具查阅多个模块、提交修改、获取公开测试反馈，并由独立隐藏测试最终评分。不比较技能效果，不以单例宣称真实仓库性能。

## 固定条件

- baseline，无额外技能；deepseek-flash 非思考模式，temperature=0。
- investigate → implement → verify 固定三阶段，切换阶段重建消息，仅传递必要摘要；文件修改状态保留。
- 最多 10 次模型请求，每阶段最多 4 次；每次最多输出 2,048 tokens；请求消息与工具 JSON 不超过 64 KiB；SDK 不自动重试。
- 按此前核实的官方高峰价作费用上界估算，预算 USD 0.25，字节/分词预留不是账户账单保证。
- 整个运行允许模型最多请求两次公开测试；最初自动运行的公开测试和最后的隐藏评分另计为非模型调用。

## 工具与隔离

允许列文件、读取可见文件、原子替换允许修改的文件、运行公开测试和结束当前阶段。不提供任意宿主机 shell。只有 implement 阶段允许修改。

候选工作区在内存中维护；Python 模块通过受信任的引导程序在 Docker 中导入，宿主机不执行项目代码。容器仍只挂载一个包含候选模块数据的入口文件，不接收本机密钥或评分源码。

当前仅支持可导入的 Python 源码及普通 JSON 函数参数，不具备真实仓库文件系统、资源文件、子进程任务或命名空间包支持。

## 验收与记录

最初公开测试应暴露原始缺陷。模型通过工具提交修改后，外部隐藏测试给出最终结果。公开反馈不包含隐藏测试内容。保存全部工具请求/响应、候选源码、评分日志、预算、用量和错误分类。

通过、失败、预算耗尽、无效输出、接口或环境错误均保留，不自动重复付费调用以替换结果。工程故障修复后的新运行必须独立记录。

参考实现演示属于另一条不调用模型的确定性验证，已明确标注修复来自人工参考；不得混同为 Agent 结果。

运行命令：

```powershell
.\.venv\Scripts\python.exe -m scripts.repo_agent --output results/repo-agent-smoke-20261123
```

## 版本 2：修正并行查阅的工程限制

首次运行收到一条包含 6 个合法文件查阅操作的模型响应，被原型内部的“最多 4 个工具调用”限制拒绝。它只进行了 1 次模型请求，用量 1,166 tokens，未修改源码、未进入隐藏评分。该记录保留；这里的 invalid_output 来自原型协议限制，不能作为模型修复能力失败。

修订版将单条响应工具上限设为 18（最多 16 个可见文件，加清单和公开测试项），并在提示中明确声明。每阶段仍最多 4 次模型请求，整个运行仍最多 10 次请求；读写范围、公开测试次数和文件大小上限不变。新增测试覆盖一次 6 个合法读取操作。

修订版只做一次独立冒烟测试，不覆盖首次记录。两次运行的已知费用估算加修订版的保守请求预留须小于原 USD 0.25 预算。首次原型保留在 bbb9ff7 提交中，修订方案与修订代码在第二次请求前提交。
