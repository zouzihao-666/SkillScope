# 第三阶段：怎样理解这轮实验

这一阶段从“能跑一道题”，推进到“同一套材料下比较多种配置，并保留全部结果”。固定方案见 [实验方案](stage3-protocol.md)。

## 1. 扩展任务和技能

6 份指南覆盖调查、最小修改、边界、校验、兼容性和 Python 惯用法。4 道开发题覆盖数值边界、区间合并、路径转义和拓扑排序。

作用：用不同类型的题目观察技能影响，减少仅凭一道简单题作判断。它们仍是人工编写的教学任务，尚不足以代表真实仓库。

另外 2 道保留题不参与模型实验。参考实现只检查评分器，不进入模型消息。

## 2. 先检查考卷和评分方式

```powershell
.\.venv\Scripts\python.exe -m skillscope corpus-check --output results/my-corpus-check
```

作用：确认正确参考实现能通过、缺陷初始实现会失败。该命令调用 Docker，不请求模型。每次指定新的输出目录，避免覆盖旧检查。

## 3. 比较 12 种配置

| 配置 | 用途 |
| --- | --- |
| baseline | 看模型不带指南时是否能做题 |
| single-* 共 6 组 | 区分单个指南的影响与组合的影响 |
| all | 同时加载所有指南 |
| scoped | 在规定阶段加载相应指南 |
| all-reversed | 保持指南内容相同，只反转加载顺序 |
| length-a、length-b | 保留相同字符数，换成两种无关描述文本 |

作用：更多指南既改变指令，也让输入变长，还可能改变顺序。对照可以帮助发现这些因素是否值得继续研究。字符数量相同不等于 token 数相同，无关文本自身也不是完全没有影响。

只查看计划，不花 API 额度：

```powershell
.\.venv\Scripts\python.exe -m skillscope plan --config benchmarks/stage3/experiment.json --controls --output results/my-stage3-plan.json
```

默认 4 题 × 12 配置 × 3 次重复 = 144 次主实验。排期被打乱，种子只控制排期，不能控制服务端模型随机性。

## 4. 基线预检与真实批次

正式对照前，4 道开发题各做一次无技能预检；至少 2 道通过才继续。预检不进入主对照统计。

```powershell
.\.venv\Scripts\python.exe -m skillscope batch --config benchmarks/stage3/experiment.json --output results/my-stage3 --repeats 3 --seed 731 --workers 3 --max-calls 444 --max-total-tokens 1000000 --max-usd 1
```

这条命令会付费调用 API，不需要为了看结果重新执行。已完成的结果可以通过报告命令重读。

作用：事先冻结任务、指南、测试、排期、源码和评分镜像；对并发任务预留预算；保存每一次输出。发生接口、环境或用量错误时停止启动新任务，避免自动重试造成额外支出。

USD 1 是按固定官方高峰价作的上界估算预算，并不是账户账单保证。程序同时限制调用次数、报告 token 用量和每次输出长度。

## 5. 读取报告，不重新请求模型

```powershell
.\.venv\Scripts\python.exe -m skillscope report results/stage3-20261123
```

作用：从已有记录生成 report.md 和 report.json，不消耗模型额度。

- 完成率：在可判定的运行中，有多少次完成任务。
- 未知：接口、环境错误或缺失记录，不当作普通模型答错。
- 失败分项：测试失败、无效输出、超时和预算耗尽分别保留。
- 描述区间：提醒少量重复不能得到确定结论。温度为零和缓存可能使结果相关，不能把描述区间当作新任务的保证。
- 对应比较：在同一题目、同一重复编号下比较改善与退化次数；不是共享模型随机种子的严格配对实验。

## 6. 什么情况才值得继续诊断

本轮预先规定：某题的基线及全部单技能都通过 3 次，而全部加载至少失败 2 次，才列为待复核的重复退化候选。

即使出现候选，也还要看无关文本、反向顺序和阶段加载的结果。单个技能本身就失败时，不能直接归因于组合冲突。

如果各组都通过，说明这轮没有观察到目标现象。合理下一步是预先设计更复杂、更接近真实仓库的任务，再测试假设；不事后改题或加入故意答错的指南来制造发现。

## 7. 归档和续跑

本地原始记录在 results/stage3-20261123，公开证据将归档到 artifacts/stage3-20261123。

断点续跑需要加 --resume，并保持原来的预算、种子、重复次数、输入、源码和镜像。已完成调用不会重复执行；不完整运行目录表示费用可能未知，需要人工核查。不要同时启动两个指向同一输出目录的批次。

压缩原始日志逐行保留请求、响应、候选代码和运行摘要。日志不包含 HTTP 认证头或本机密钥；失败评分日志的宿主机路径在公开副本中替换为占位符。
