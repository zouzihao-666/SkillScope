# 完整诊断工具的执行前约定

## 这次交付的范围

将已完成的运行与评分能力接入完整工具链：统一命令、自动集合缩减、单技能/组合分类、阶段方案构造、开发题选择、固定方案后的保留题验证、中文与 HTML 报告、证据导出。

旧实验的组合候选门槛与记录不修改。新工具诊断的是“技能引入的退化来源”，同时允许得到单技能干扰、组合候选、基线不可靠、未复现或证据不足。没有充分证据时不把一种类别改名为另一种，也不承诺某个技能必然有害。

## 固定配置与新样本

使用仓库根目录 diagnosis.json，模型仍为 deepseek-flash，非思考、请求 temperature=0，每次运行最多 10 次请求、阶段最多 4 次、输出最多 2,048 tokens。每个配置新跑 3 次。全部加载与各对照使用同一执行协议。总结超过 2,000 字符时明确记录原长度和截断标记，仅保留已有文本的前 2,000 字符，不再把这类长度超限直接算成整次失败。

开发题为 dotenv-backslash。旧数据只把 edge-cases 和 input-validation 排为复核线索；工具先取得新基线和新全部加载数据，再从旧低成功技能中优先新测最差一项。旧成功/失败次数不填入新重复记录。

新测全部配置没有未知评分且通过比例至少 2/3 才标为 good，至多 1/3 才标为 bad；其余及缺失评分为 unknown。若新基线不可靠，不归因技能。

## 自动缩减和分类

对重新得到的 bad 集合使用分块删除及单项删除，缓存相同任务、相同阶段映射的测量，逐步寻找较小仍为 bad 的集合。每次删除都保留三次评分或未知记录。最多查询 6 个不同集合，命中已有测量不新增付费调用，仍受总预算限制。

最后只剩一个技能时，标为单技能退化；剩多个时需要分别测试其单技能，才可能标为组合候选。测试不足则保留“混合退化、归因未完成”。只承诺预算内检查的一阶删除最小性，不保证全局最小或因果证明。

## 阶段方案与比较

自动方案保留其他指南在全阶段加载，只把可疑技能限制到它原先声明的阶段；它是按诊断结果构造的明确规则，不是训练或学习的最优策略。同时测量人工阶段声明、固定词重合排序选前两份指南的相关性基线，以及可疑技能移除方案。

在有效评分完整且通过数不低于基线与全部加载的方案中，先选通过数最高者，同分时保留更多指南—阶段位置，再按方案名确定排序。重复使用同一配置时共享旧测量并明确标注，不声称是新增独立重复。

将选中方案写入 policy.json 并固定 SHA-256 后，才允许调用 dotenv-bom 保留题。保留题比较无技能、全部加载、选中方案，各 3 次。该题从未被之前的模型实验调用或评分；从本轮开始一旦使用，必须标记为“已使用”，以后不能继续称为未见保留集。保留评分不重新选择或修改方案。

## 预算、失败和验收

本次完整工具验收最多 36 次运行、360 次请求、固定价格估算上限 USD 1.50。整次请求预算在发起前预留；未知用量保留整次上限并停止新增调用。费用估算不是账单，不自动重试。为策略比较和保留题保留运行/请求额度，不能先把所有额度耗在搜索上。

输入、源码、镜像在调用前固定。每次写入预算和结果，有 OS 文件锁防止重复启动；进程中断后仅复用已落盘且来源吻合的结果，不重发无法确认用量的请求。

工程验收包括：确定性测试证明 reducer 能找到单技能和交互集合、未知与预算不会被当成退化；伪造策略不能开启保留题；缓存/中断恢复不重复调用；HTML 转义；安装包可在仓库目录外使用。真实 API 验收无论是否发现退化都发布完整记录，不能以“通过”为由隐藏失败。

## 初次工程验收与 v0.6.1 修订

提交 de61b88 后的 6 次工程验收记录完整保留：新基线通过 1/3，全部加载通过 3/3，60 次请求、313,848 tokens、USD 0.074678124 估算。原逻辑因基线不可靠而直接返回，未生成有效策略，也未开启保留题。

v0.6.1 在阶段输入中提供最多 24 KiB 的当前可编辑源码，减少重复读取；保留旧消息隔离，源码可能携带间接影响。基线不可靠时仍禁止技能归因，但允许比较并选择实际表现好的配置，包括保留全部加载；不会因为必须“发现坏技能”才交付方案。未选出方案时也生成明确标为 unvalidated 的文件。

冻结文件的导出精确保留原字节，策略和计划的 SHA-256 在导出后仍一致。新样本不与初次六项合并成功率。v0.6.1 新验收最多 30 次运行、300 次请求、USD 1.40，加上前六项仍不超过本次承诺的 36 次、360 次与 USD 1.50；输入变化后使用新目录，不覆盖旧记录。保留题仍只在新策略冻结后允许调用。
