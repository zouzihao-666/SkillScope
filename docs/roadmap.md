# 开发路线与验收条件

## 第 1 阶段：实验准备（本次实现）

- [x] 独立 Python 项目与命令行入口。
- [x] 技能、任务、数据划分、阶段的数据校验。
- [x] 无技能、单技能、全部加载、阶段加载的平衡重复排期。
- [x] 固定排期随机种子，保存内容快照及 SHA-256 指纹。
- [x] 阶段消息预览，不包含独立评分测试。
- [x] 工具测试，以及 Windows/Linux CI 配置。

验收：默认排期 15 次、阶段指南符合设置，工具测试通过。此阶段没有模型成绩。

## 第 2 阶段：跑通一次真实任务

- [x] 本机读取密钥，接入 DeepSeek `deepseek-flash`，固定非思考配置。
- [x] LangGraph 固定调查、修改、验收流程，各阶段重建消息。
- [x] 受限提交工具、代码和必要记录传递，记录请求与响应模型标识。
- [x] Docker 执行候选代码，评分由宿主机可信测试通过 JSON 代理完成。
- [x] 请求超时、调用次数、输出长度、token 使用量记录；单独记录错误与预算耗尽。
- [x] 固定依赖与基础镜像摘要，保存输入、候选代码、评分与调用日志。

验收：一道题、一个配置完成真实调用与独立评分，退出时清理环境。没有密钥时清楚报错，不用模拟成绩替代数据。

已完成两次真实试运行。当前仅支持教学函数任务，尚不支持通用仓库工具或任意 Python 对象。模型检查阶段不能替代最终独立评分。

## 第 3 阶段：寻找稳定退化

- [ ] 扩展至 6–10 个技能、更多 discovery 任务和重复实验。
- [ ] 先确认无技能配置能完成足够多任务，避免全部失败无法比较。
- [ ] 记录完成率、预算、费用和不确定性，不把调用错误当作模型做题失败。
- [ ] 增加加载顺序、长度相近的多种对照文本。
- [ ] 找不到稳定案例时，记录负面结果并调整假设。

验收：原始运行日志支持稳定退化，或明确报告证据不足。

## 第 4 阶段：诊断与策略

- [ ] 预算内逐步缩小技能组合，保留重复实验和不确定性。
- [ ] 不宣称保证找到全局最小冲突集合。
- [ ] 生成阶段策略，与全部加载、相关性选择、人工阶段策略公平比较。
- [ ] 策略固定后在新 holdout 任务验收，计入诊断与策略选择成本。

验收：公开原始结果与复现入口，报告成功及失败案例，限定适用任务与模型。
