# 第三阶段之后的执行路线

依据：第三阶段 144 次主实验只有一次调查输出截断，没有达到预先规定的重复组合退化模式。因此先复核预算和评测区分度，再进入诊断与策略。

## 第 1 步：预算敏感性复核

作用：确认已观察到的截断是否在相同题目、相同配置下重复出现，并比较扩大输出预算后的表现。

固定第三阶段原题 get-path、原 6 份技能与原评分器。比较 baseline、all、all-reversed、scoped，每组分别使用 1,024 与 2,048 tokens 的单阶段输出上限，各重复 5 次：共 40 次运行，最多 120 次请求。每档预算应用于全部三个阶段，不声称只隔离了调查阶段的作用。

固定 seed=1041，打乱全部任务顺序，最多并发 2 次；不复用第三阶段的失败或成功记录。温度、模型与工具协议不变。按既有官方高峰价计算费用上界估算，预算 USD 0.50，报告 token 上限 500,000；不自动重试付费请求。

执行前冻结方案、源码指纹、语料、镜像和排期。测试失败、截断和接口/环境错误分开记录。完整保留所有结果，不按结果增删重复。

验收：40 次运行有完整记录，或明确报告预算/外部故障导致的不完整；逐配置、逐预算报告成功和截断次数。低预算至少 2/5 截断、高预算 0/5 截断且 5/5 通过，才标记为待复核的预算敏感模式；不据此证明因果或泛化。没有复现时如实报告。

## 第 2 步：多文件项目运行器

作用：从单函数提交升级到跨模块查阅、修改和测试，让 Agent 的操作顺序和阶段指南有实际发挥空间。

工具限定为列文件、读文件、写允许修改的文件和运行公开测试；不提供任意宿主机 shell。候选代码只在 Docker 中执行，最终评分文件与密钥不进入候选工作区。增加路径、文件数量、内容大小、调用次数和超时限制。

先用人工编写的多文件夹具验证工程链路，并明确标注它们不是来自真实开源 issue。

验收：能复现原始公开测试失败、由候选补丁修复、通过外部隐藏测试；越界写入、修改评分器与超时用例均有检查。该步骤的 API 冒烟运行另行固定预算与排期。

## 第 3 步：任务难度校准

作用：避免下一轮所有配置仍然全部通过，或全部失败而无法比较。

建立带来源、许可证、固定提交与独立评分的真实仓库任务池。先分开发集与新的保留集，再做少量无技能试运行；保留集不用于调试、选题或阈值调整。若开发集仍然全部通过，应扩大任务池和推理/工具复杂度，并报告筛选过程。

验收：公开任务来源和预先固定的筛选标准，开发集具有可测成功/失败空间；不从看过保留集结果后回头选题。

## 第 4 步：新一轮技能对照

作用：在有区分度的任务上比较技能内容、组合、顺序和上下文长度。

固定模型、任务、技能、预算及指标后，再重复无技能、单技能、组合、阶段策略、顺序和多种长度对照。校准成本一并计入，预算造成的失败与语义错误分开报告。

验收：形成可以复查的重复退化候选，或明确报告证据不足。旧数据不被新实验覆盖。

## 第 5 步：组合诊断与策略验证

作用：有证据后，定位较小的冲突组合，并验证阶段隔离是否缓解问题。

在固定预算内逐步移除技能，每个保留的退化判断都有重复证据；不承诺全局最小集合。策略与全部加载、相关性选择和人工阶段规则公平比较。策略固定后再开启新保留任务验收。

验收：公开完整成本、原始记录、成功与失败案例。若前一步仍无稳定候选，则保持该步骤未启动，不用故意答错的技能制造结果。
