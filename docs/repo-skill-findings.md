## 从失败记录学到了什么

反斜杠题要求同时修复“写入后读回”和解析器的转义行为。三次 edge-cases 失败补丁均只改了解析器；两次 all 失败补丁也只改了解析器，遗漏写入端。成功的 all 和两次有效 scoped 样本同时修改了两个模块。

通俗地说，部分模型修好了“读”的一边，却漏了“写”的一边。这提示跨模块调查、实现阶段的请求分配和公开反馈利用值得进一步复核；这些轨迹不足以证明指南语义互相冲突。

scoped 的一次格式失败发生在调查阶段：模型提交的总结为 2,087 字符，超过固定的 2,000 字符上限。未进入最终评分，单独记为 invalid_output，不记为补丁功能错误。原始失败不按结果补跑替换。
