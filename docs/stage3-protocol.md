# 第三阶段预先固定的实验方案

方案版本：2026-11-23 / v0.3。先提交本方案，再执行本批次；不根据结果修改本批次任务、测试、技能或阈值。

## 目标和假设

观察多个技能共同加载是否比无技能及各单技能稳定变差，并比较顺序和上下文长度对照。不预设必须出现正面发现。

本阶段只覆盖人工编写的函数修复教学任务，无法代表真实代码仓库或所有 Agent 技能。

## 任务与分组

- 6 份技能指南；4 道 discovery 题；2 道 holdout 题不请求模型。
- 12 组：无技能、6 组单技能、全部加载、阶段加载、反向全部加载、2 组无关文本。
- 无关文本保留同样的技能标签与字符数量，替换正文。字符等长不保证 token 等长，标签和文本本身仍可能影响结果。记录实际模型输入 token 用量。
- 全部加载与反向加载使用完全相同的技能正文，只改变顺序。
- 每题每组重复 3 次，共 144 次主实验，固定排期种子 731，打乱全部主实验顺序，最多并发 3 次运行。

## 基线预检

先对 4 道开发题各运行 1 次无技能配置。至少 2 道通过才继续主实验。4 次预检不进入主对照统计，也不复用为主实验重复。

评分器先在 Docker 中分别运行每题的正确参考实现和缺陷初始实现；必须分别通过和失败，再进行付费实验。模型只看到题目与初始代码，参考实现和测试源码不会进入提示或候选容器。

## 运行设置和预算

固定 deepseek-flash、非思考模式、temperature=0、每阶段最多输出 1,024 tokens，三个阶段各一次请求，不自动重试。

基线预检加主实验最多 148 次运行、444 次模型请求；报告 token 上限设为 1,000,000，按并发未完成请求预留保守额度。请求消息与工具文本 JSON 限 64 KiB。

费用按 [DeepSeek 官方高峰单价](https://api-docs.deepseek.com/quick_start/pricing/)作上界估算：每百万缓存命中输入 USD 0.006、未命中输入 USD 0.30、输出 USD 1.20；估算预算 USD 1。价格核验日期为 2026-11-23。输入的字节预留只是分词上界近似，币值并非账户账单或汇率换算。

发生 API、环境错误或用量缺失时停止启动新任务，已启动任务在预留预算内结束。结果缺失时不编造用量或成绩，不自动重试收费请求。断点续跑必须匹配冻结输入、代码、镜像和预算；不完整运行目录需要人工核查，不会被自动重复调用。

## 记录与报告

保存冻结输入、完整排期、源码指纹、镜像 ID、全部请求/响应、候选代码、测试结果、使用量、费用估算和错误类别。

- passed：独立测试通过。
- failed、invalid_output、timeout、budget_exhausted：模型系统未完成任务，计入任务失败并分项报告。
- api_error、infrastructure_error、internal_error、interrupted 或缺失：保持未知，不冒充普通模型失败。
- 同时报告成功数、可判定分母、未知数和缺失结果下的上下界，避免隐去错误后只报告有利完成率。
- 逐题、逐重复编号对应比较改善/退化次数。重复编号并不是共享的模型随机种子。
- Wilson 95% 区间仅在独立伯努利近似下作描述。温度为零、缓存和固定任务会使结果相关，不能据此推断新任务总体效果。计算参考 [NIST 方法说明](https://itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。

## 候选与负面结果

对某题，仅当基线与全部 6 组单技能均通过 3 次、全部加载在 3 次中至少失败 2 次，才列为重复退化候选。分别展示两种长度对照、反向加载和阶段加载的结果；这些观察不能单独证明内部因果机制。

此规则只筛选待复核候选，不输出全局最小冲突集，不执行第四阶段的自动策略学习。

若找不到该模式，报告证据不足；若大多配置全部通过，说明当前任务可能存在天花板效应，下一轮应预先固定更复杂的真实任务，而不是事后修改本批次规则制造冲突。
